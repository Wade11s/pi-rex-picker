### Worktree and simulator cleanup

**The audit is read-only. Its buckets are advice, never deletion permission.** This playbook can destroy user state, so explicit gates replace code review.

1. Snapshot and audit. Record `df -h /` when supported, then run the resolved `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` after the preflight in `references/script-runtime.md` (principle-build-the-lever). Without `-b`, merge checks use `origin/HEAD` with `main`/`master` fallbacks; pass the actual target ref when different. Worktree paths come from `git worktree list`, not guessed directory layouts (principle-encode-lessons-in-structure). The script reads existing local refs and forge metadata. It never fetches, changes refs, deletes worktrees, or writes to a remote. If the base is stale or absent, report that limit and refresh it only as a separately authorized step.
2. History is optional. By default the audit reads no agent history and omits history columns. Only supply `PSTACK_TRANSCRIPTS_DIR` when the host or user explicitly provides an authorized directory scoped to this user and project. Do not derive it from a vendor cache, scan other projects, or turn transcript IDs into guessed chat URLs. If the host only exposes a history API, keep that separate from the script and scope it explicitly. Missing history means usage is unknown, not inactive.
3. Verify usage. Get the active/pinned session and process set from the user or an available authorized host interface. Cross-check candidates and worker-created sibling worktrees, including dev servers and simulators. A transcript mention or its absence does not prove liveness. Use workers for large authorized exports only when available; otherwise inspect bounded material sequentially and disclose the gap. Never fabricate a pinned-state report from a transcript.
4. Pause on possible loss. Inspect tracked, untracked, and ignored files before proposing deletion. `wip:N` and `scratch:N` are counts, not proof that the files are disposable. Unknown usage, unpublished commits, active work, and missing metadata hold the candidate. Show the exact candidate paths and risks and obtain deletion authorization, even for a clean merged tree. A generic "clean up" request does not authorize unlisted user-data loss.
5. Prune only the approved set. Prefer `git worktree remove <path>`. If it refuses, inspect why and obtain approval for any force removal or ignored-file deletion. Never use a blanket `rm -rf` fallback. Keep branch refs unless separately authorized. Re-list with Git and record disk space again, marking unavailable measurements instead of inventing reclaimed bytes.
6. Other reclaimers are separate opt-ins. On macOS with Xcode tools, list simulator devices/runtimes and propose exact unused IDs before deletion; do not delete all clones or runtimes by default. For IDE state, backups, package caches, or build outputs, use documented host locations and a user-approved candidate list. Missing platform tooling skips that check with a limitation, not an installation or a speculative path scan.

**Reply, in the user's language:** measured disk usage before/after when available, exact approved worktrees removed, each held candidate and reason, and any history, forge, or platform evidence that remained unavailable.
